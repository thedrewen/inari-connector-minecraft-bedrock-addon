# InariConnector

Minecraft Bedrock Edition addon that connects a server to Inari through
WebSocket.

The addon initializes players, periodically sends their position, view
direction, and mute status, and automatically attempts to reconnect when the
connection is closed.

## Features

- WebSocket connection to Inari when the world loads.
- Server authentication with an API key.
- Periodic synchronization of connected players.
- An Inari code assigned to each initialized player.
- Commands for displaying a code and managing mute status.
- Connection and reconnection messages sent to players with the `staff` tag.

## Requirements

- Minecraft Bedrock Edition Vanilla Server.
- An Inari WebSocket URL.
- A valid Inari API key.

The project versions are declared in `package.json`:

- TypeScript `7.x`.
- `@minecraft/server` beta.
- `@minecraft/server-admin` beta.
- `@minecraft/server-net` beta.

## Installation

Clone the project and install its dependencies:

```bash
npm install
```

Then configure the values for your server in:

```text
config/default/variables.json
config/default/permissions.json
```

Example `variables.json`:

```json
{
	"INARI_WS_URL": "wss://inari.example.com/ws",
	"INARI_API_KEY": "your-api-key"
}
```

Replace the example values before starting the server. Never publish the API
key in a public repository.

> **Note:** the API key is stored in `variables.json` and not in
> `secrets.json`, because Bedrock secrets cannot be used with WebSocket
> connections, so the addon would be unable to use it.

## Build

Compile the TypeScript source into the `scripts/` directory:

```bash
npx tsc
```

The generated entry point is `scripts/main.js`, as declared in
`manifest.json`.

## Installing in Minecraft

1. Build the project with `npx tsc`.
2. Place the addon folder in Minecraft's behavior pack directory.
3. Activate the behavior pack on the target world.
4. Make sure the required scripting modules are available in your Minecraft
	 version.
5. Start the world and check the server logs.

The manifest declares `scripts/main.js` as the script module entry point.

## Minecraft Commands

### `/inari:inari`

Displays the player's Inari code.

### `/inari:mute`

Allows a player to mute themselves.

### `/inari:deafen`

Allows a player to deafen themselves (nightly protocol, Inari `1.7.0-nightly`).

### `/inari:admin`

Opens the admin panel (operators only): lists players with their status (muted, deafened, force muted, force deafened) and lets you toggle force mute / force deafen, which sets or removes the `muted` / `deafened` tags.

## Force Mute

To force mute a player, simply add the `muted` tag to them:

```mcfunction
/tag <player> add muted
```

To remove the force mute, remove the tag:

```mcfunction
/tag <player> remove muted
```

## Force Deafen

Requires an Inari server on the `nightly` tag (`1.7.0-nightly`), where `is_force_deafened` is a required field of `sync_connector_state`. It is also ignored by stable servers, so it is always sent.

```mcfunction
/tag <player> add deafened
/tag <player> remove deafened
```

## Project Structure

```text
src/                  TypeScript source code
src/main.ts           Addon entry point
src/entities/         Entity and player initialization
config/default/       Configuration variables
scripts/              Generated JavaScript files
manifest.json         Behavior pack declaration
tsconfig.json         TypeScript 7 configuration
```

JavaScript files in `scripts/` are generated by the compiler. Modify the code
in `src/`, then rebuild the project.
